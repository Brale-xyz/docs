---
title: 'Simulate an Automation deposit'
description: 'Simulate an inbound ACH, wire, or FedNow deposit into a testnet Automation and run the normal Transfer, mint, and webhook flow without moving real fiat.'
openapi: '/api-reference/brale-openapi.yaml POST /accounts/{account_id}/automations/{automation_id}/simulations/deposits'
---

Testnet Automations return placeholder banking coordinates that cannot receive real deposits. Use this endpoint to simulate an inbound ACH, wire, or FedNow deposit instead. Brale creates a simulated inbound payment, runs the normal Automation mint path, and returns the resulting Transfer. Brale does not contact a bank, and no real fiat moves.

**POST** `https://api.brale.xyz/accounts/{account_id}/automations/{automation_id}/simulations/deposits`

Required scopes: `automations:write` and `network:testnet`

<Note>
  This endpoint is available only with testnet credentials. The Automation must belong to the account in the path, have `status: "active"`, and have a destination on a testnet chain, such as `base_sepolia` or `solana_devnet`.
</Note>

## Path parameters

| Parameter | Type | Required | Description |
| :-------- | :--- | :------- | :---------- |
| `account_id` | string (KSUID) | Yes | The account that owns the Automation. |
| `automation_id` | string (KSUID) | Yes | The testnet Automation to fund. |

## Headers

| Header | Required | Description |
| :----- | :------- | :---------- |
| `Authorization` | Yes | `Bearer <token>` from testnet API credentials. |
| `Idempotency-Key` | Yes | A unique key for this simulated deposit. See [Idempotency](#idempotency). |

## Request body

The request body accepts only the fields below. Brale rejects additional properties.

| Field | Type | Required | Description |
| :---- | :--- | :------- | :---------- |
| `amount.value` | string | Yes | Positive decimal amount greater than zero, such as `"10.00"`. |
| `amount.currency` | string | Yes | Must be a reserve currency accepted by the API, such as `USD`. |
| `transfer_type` | string | Yes | Inbound rail to simulate. Accepted values: `ach`, `wire`, `fednow`. These are simulator inputs, not Transfer rail identifiers. `fednow` produces a Transfer with `source.transfer_type: "fednow_credit"`. Do not send `fednow_credit` here. |

## Examples

<CodeGroup>

```bash FedNow
curl --request POST \
  --url "https://api.brale.xyz/accounts/${ACCOUNT_ID}/automations/${AUTOMATION_ID}/simulations/deposits" \
  --header "Authorization: Bearer ${AUTH_TOKEN}" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: $(uuidgen)" \
  --data '{
    "amount": { "value": "1.00", "currency": "USD" },
    "transfer_type": "fednow"
  }'
```

## Response

### 202 Accepted

Returns the standard [Transfer](/key-concepts/transfers) representation. There is no separate simulation resource. The Transfer includes `automation_id`, and `source.transfer_type` records the simulated rail. For a `fednow` simulation, `source.transfer_type` is `fednow_credit`. The Transfer also includes `funding_simulated: true` and synthetic `source.payment_details`. See [Synthetic payment details](#synthetic-payment-details). `202 Accepted` means Brale accepted the simulated deposit. It does not mean the mint is complete.

### Synthetic payment details

Brale adds synthetic `source.payment_details` to every simulated deposit so you can test reconciliation. The values use production formats but are not real. Brale stores them with the Transfer, so [Get a transfer](/api-reference/brale/get-transfer) returns the same values as the `202` response. Retrying with the same `Idempotency-Key` returns the same details.

| Field | `ach` | `wire` | `fednow` |
| :---- | :---- | :----- | :------- |
| `received_at` | Time Brale accepted the simulated deposit | Same | Same |
| `sender_name` | `Simulated Sender` | `Simulated Sender` | `Simulated Sender` |
| `sender_bank_name` | `null` | `Brale Simulated Bank` | `Brale Simulated Bank` |
| `sender_bank_routing_number` | `110000000` | `110000000` | `110000000` |
| `trace_number` | 15 digits: `11000000` followed by 7 random digits | `null` | `null` |
| `imad` | `null` | 22 characters: the date as `YYYYMMDD`, `SIMBRALE`, then 6 random digits, such as `20261111SIMBRALE482913` | `null` |
| `payment_reference` | `null` | `Simulated wire ` followed by 8 random digits | `Simulated FedNow ` followed by 8 random digits |

The random digits differ on each new simulated deposit. Do not rely on specific values.

Simulated deposits also return `funding_simulated: true`. Real deposits never include synthetic details.

Fetch the Transfer with [Get a transfer](/api-reference/brale/get-transfer) to follow it to `complete` and read `destination.transaction_id` for the testnet mint.

## Errors

| Status | `type` | When |
| :----- | :----- | :--- |
| `400` | Schema validation error | `transfer_type` is not `ach`, `wire`, or `fednow` (for example, `rtp` or `fednow_credit`), a required field is missing, or the body includes an unknown field. |
| `400` | `invalid_currency` | `amount.currency` is not a reserve currency accepted by the API (for example, `EUR`). |
| `400` | `invalid_amount` | `amount.value` is malformed, zero, or negative. For zero, `detail` is `Amount must be greater than zero`. |
| `401` | | Missing or invalid bearer token. |
| `403` | | The credentials do not include `network:testnet` or another required scope. Mainnet API keys receive this response. |
| `404` | | The account or Automation was not found, or the Automation does not belong to the account in the path. |
| `422` | `mainnet_destination` | The Automation destination is on a mainnet chain. `detail` is `Deposit simulation is only available for testnet automations`. |
| `422` | `automation_not_active` | The Automation is pending, disabled, archived, or otherwise inactive. `detail` is `Automation must be active to simulate a deposit`. |
| `422` | | The `Idempotency-Key` was already used with a different request body or URI. |

## Idempotency

`Idempotency-Key` is required, as on every `POST` request. See [Idempotency](/key-concepts/idempotency).

- Send a new key to create a new simulated deposit.
- Retry with the same key and the same body to get the cached `202` response. The retry does not create a second payment, Transfer, transaction, or mint.
- Reusing a key with a different body or URI returns `422` and does not create another mint.

## Webhooks

Brale emits the normal `payment.completed` [webhook event](/webhooks/webhook-events) for the simulated inbound payment, followed by the normal `transfer.*` events as the Transfer progresses. There is no simulation-specific webhook type. `transfer.*` events do not include `payment_details`. For `wire` and `fednow` simulations, `source.transaction_id` in `transfer.*` events is the synthetic `payment_reference`. Simulation creates simulated fiat funding only. It does not test a real bank or the FedNow network. See [Receive FedNow deposits](/guides/fednow-inbound#test-on-testnet).
