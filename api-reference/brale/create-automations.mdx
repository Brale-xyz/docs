---
title: 'Create an Automation'
description: 'Create an automation that mints stablecoins to a destination wallet when fiat deposits are received.'
openapi: 'POST /accounts/{account_id}/automations'
---
Use the playground below to try this endpoint directly, or review the OpenAPI details in the right panel.

## Source configuration

Set `source.value_type` to `USD` and omit `source.transfer_type`. A USD Automation is not tied to a single deposit rail. Its virtual account accepts the inbound rails enabled for it, such as wire, ACH, and FedNow (on accounts with FedNow enabled). Responses may return `source.transfer_type: null`.

The rail used for each deposit appears on the resulting Transfer in `source.transfer_type`, for example `fednow_credit`. This is a Transfer response value, not an Automation setting. See [Receive FedNow deposits](/guides/fednow-inbound).

## Branded Automations

You can optionally include a `brand` object in the request body to select the verified identity (business or individual) that appears as the beneficiary on the automation's funding instructions.

| Field | Type | Required | Description |
| :---- | :--- | :------- | :---------- |
| `brand` | object | No | Controls the beneficiary shown on the Automation's funding instructions. |
| `brand.account_id` | string | Yes (if `brand` is provided) | The account whose verified identity appears as the beneficiary. Can be the caller's own account or a managed account. If the account is a business, its business name and address are used. If the account is an individual, the individual's legal name and address are used. |

<Note>
  **Default behavior is unchanged.** If you omit `brand`, the beneficiary on funding instructions defaults to Brale. If you include `brand.account_id`, the beneficiary reflects that account's verified business or individual identity instead.
</Note>

The automation is still created under the account in the request path (`/accounts/{account_id}/automations`). `brand.account_id` does not change which account owns the automation — it only selects the identity shown on the funding instructions.

<Note>
  **Testnet branding.** With testnet credentials, you can create branded Automations using a business or individual account you have access to, without completing mainnet KYB/KYC or enabling that account for mainnet. Testnet funding instructions contain placeholder banking details and cannot receive real deposits. To fund a testnet Automation, use [Simulate an Automation deposit](/api-reference/brale/simulate-automation-deposit). Mainnet verification requirements are unchanged.
</Note>

### Example: branded automation request (business account)

```json
{
  "name": "XYZ Onramp",
  "source": {
    "value_type": "USD"
  },
  "destination": {
    "address_id": "2VcUIIsgARwVbEGlIYbhg6fGG57",
    "value_type": "SBC",
    "transfer_type": "solana"
  },
  "brand": { "account_id": "34lCJZ2bxbPAzB3ou67Md01veUo" }
}
```

### Example: branded automation request (individual account)

Pass the `account_id` of an individual account to render that person's legal name and address as the beneficiary. On mainnet, the individual account must be KYC-verified. See [Individual accounts](/guides/individual-accounts) for how to create one.

```json
{
  "name": "Jane Doe Onramp",
  "source": {
    "value_type": "USD"
  },
  "destination": {
    "address_id": "2VcUIIsgARwVbEGlIYbhg6fGG57",
    "value_type": "SBC",
    "transfer_type": "solana"
  },
  "brand": { "account_id": "3Ar9BnQCKIrB3SYjKGBzCtFs6XL" }
}
```

Once the Automation becomes active, `source.funding_instructions.beneficiary_name` and `beneficiary_address` in the response reflect the branded account's verified identity (business name and address, or individual legal name and address).

For more details on how branded Automations work, see the [Automations concept page](/key-concepts/automations#branded-automations).
