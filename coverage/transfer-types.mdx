## Transfer type aliases

Brale accepts these aliases anywhere a `transfer_type` is accepted as input, including Address creation and updates, Address list filters, balance lookups, and Transfer creation and list filters. Responses always return the canonical API id.

| Alias | Canonical transfer\_type (API id) | Name |
| --- | --- | --- |
| `tx` | `coreum` | Tx |
| `tx_testnet` | `coreum_testnet` | Tx Testnet |
| `verona` | `xion` | Verona |
| `verona_testnet` | `xion_testnet` | Verona Testnet |

For example, a request with `transfer_type: verona` creates a Transfer that the API returns with `transfer_type: xion`. Unknown values return an `invalid_transfer_type` error.

| transfer\_type (API id) | Name |
| --- | --- |
| `wire` | Wire Transfer |
| `ach_debit` | ACH Debit |
| `ach_credit` | ACH Credit |
| `same_day_ach_credit` | Same Day ACH Credit |
| `rtp_credit` | RTP Credit |
| `fednow_credit` | FedNow Credit. Inbound through [Automations](/guides/fednow-inbound) and outbound through [Transfers](/guides/fednow-outbound). Available on enabled accounts. |

<Note>
  The [Automation deposit simulator](/api-reference/brale/simulate-automation-deposit) takes its own input values (`ach`, `wire`, `fednow`). These are not `transfer_type` identifiers. A simulated `fednow` deposit produces a Transfer with `source.transfer_type: fednow_credit`.
</Note>
