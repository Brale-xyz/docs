  **Source:** `TransferType.json`. Values are case-sensitive.
</Note>

## Legacy transfer types

Brale still accepts these legacy `transfer_type` values anywhere a `transfer_type` is accepted as input. They are deprecated. Use the current value in new integrations. API responses may return the legacy value, so treat both values as the same network when you read responses.

| Legacy transfer\_type (deprecated) | Current transfer\_type | Name |
| --- | --- | --- |
| `coreum` | `tx` | Tx |
| `coreum_testnet` | `tx_testnet` | Tx Testnet |
| `xion` | `verona` | Verona |
| `xion_testnet` | `verona_testnet` | Verona Testnet |

Unknown values return an `invalid_transfer_type` error.

## Offchain

| transfer\_type (API id) | Name |
| --- | --- |
| `wire` | Wire Transfer |
| `ach_debit` | ACH Debit |
| `ach_credit` | ACH Credit |
| `same_day_ach_credit` | Same Day ACH Credit |
| `rtp_credit` | RTP Credit |
| `fednow_credit` | FedNow Credit. Inbound through [Automations](/guides/fednow-inbound) and outbound through [Transfers](/guides/fednow-outbound). Available on enabled accounts. |

<Note>
  The [Automation deposit simulator](/api-reference/brale/simulate-automation-deposit) takes its own input values (`ach`, `wire`, `fednow`). These are not `transfer_type` identifiers. A simulated `fednow` deposit produces a Transfer with `source.transfer_type: fednow_credit`.
</Note>
