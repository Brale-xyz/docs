<Update label="2026-06-22" description="Week of June 22" tags={["New", "Update", "Fix"]}>
  This week's updates expand webhook coverage, add new endpoints for managing addresses, automations, and verification, and broaden network support.

  ## New

  ### Worldchain support

  Brale now supports Worldchain as a transfer type on both mainnet (`worldchain`) and testnet (`worldchain_testnet`). See [transfer types](/coverage/transfer-types) for the full list of supported networks.

  ### New webhook events

  Webhook subscriptions now support additional event types so applications can react to more of the transfer and account lifecycle in real time:

  - `transfer.failed` — fires on permanent transfer failures and includes a structured `data.failure` object with `type`, `occurred_at`, `retriable`, and an `ach_return` payload for ACH returns.
  - `transfer.canceled` — fires when a transfer is canceled.
  - `payment.completed` — fires when a payment reaches `complete` status.
  - `account.verification.documents_required` — fires when KYB review requires document uploads from the account holder.
  - `account.verification.completed` — fires when account verification finishes and the account is enabled.

  See [webhook events](/webhooks/webhook-events) for payload details.

  ### Update Webhook Subscription endpoint

  You can now update a webhook subscription's destination URL and subscribed event list in place using [`PATCH /accounts/{account_id}/webhooks/subscriptions/{subscription_id}`](/api-reference/brale/update-webhook-subscription), without having to recreate the subscription.

  ### Create Internal Address endpoint

  A new [`POST /accounts/{account_id}/addresses/internal`](/api-reference/brale/create-internal-address) endpoint lets you provision additional custodial addresses on an account beyond the wallets created at onboarding — useful for segmenting funds across workflows. Deterministic chains return `active` synchronously; non-deterministic chains return `pending` until provisioning completes.

  ### Link Verification Documents endpoint

  A new [Link Verification Documents](/api-reference/brale/link-verification-documents) endpoint completes the reactive document-upload flow that pairs with the `account.verification.documents_required` webhook, letting you attach staged document submissions to an account during KYB review.

  ### Archive an Automation

  Automations can now be archived via [`PATCH /accounts/{account_id}/automations/{automation_id}`](/api-reference/brale/archive-automation) with `{"status": "archived"}`. Archiving permanently closes the virtual account and stops deposit processing — it's a terminal state.

  ## Updates

  ### Update an Address endpoint

  The [Update Address endpoint](/api-reference/brale/update-address) now supports renaming, archiving and unarchiving, and adding rails via `additional_transfer_types`, which merges into an address's existing transfer types rather than replacing them. It also accepts `bank_address` and `beneficiary_address` (wire-only) so bank addresses can be enabled for wire payouts.

  ### Get an Address endpoint

  The [Get Address endpoint](/api-reference/brale/get-address) returns the current `status`, `address` value, and enabled `transfer_types` for a single internal or external address — useful for polling asynchronous capability updates such as RTP eligibility.

  ### Refreshed Automation API schemas

  Automation request and response schemas now reflect the current `source`/`destination` shape, making automation payloads consistent with the rest of the API.

  ## Fixes

  ### Clearer Create External Address responses

  The [Create Address](/api-reference/brale/create-address) reference now documents the full `201` response and clarifies that `bank_address` and `beneficiary_address` apply only to wire when adding a bank address via direct entry.
</Update>

<Update label="2026-05-31" description="May 2026" tags={["New", "Update"]}>
  May's updates focused on real-time event delivery, smoother onboarding, more resilient payouts, and expanded network coverage.

  ## Webhooks for transfer updates

  Brale now supports webhooks for transfer events, allowing applications to receive real-time notifications instead of polling the API. Webhook deliveries use signed requests, idempotency keys, and delivery logs to support secure, auditable integrations. [Read the announcement](https://brale.xyz/blog/webhooks).

  ## Dashboard document upload for onboarding

  Customers can now upload requested verification documents directly through the Brale dashboard. Submitted documents are automatically routed into the verification workflow to reduce manual back-and-forth during onboarding.

  ## RTP fallback controls

  Organization admins can now choose whether failed RTP transfers automatically fall back to Same Day ACH.

  ## Idempotent Plaid bank registration

  Registering an already-linked Plaid bank account now returns the existing `address_id` instead of a duplicate-account conflict. Archived matching bank accounts can be unarchived and reused.

  ## Starknet support

  Brale now supports Starknet, including SBC and YSBC deployments on Starknet. See [transfer types](/coverage/transfer-types) for the full list of supported networks.
</Update>

<Update label="2026-04-30" description="April 2026" tags={["New", "Update"]}>
  April's updates focused on making transfers easier to reconcile, simplifying payout setup, expanding supported networks, and adding new developer tooling.

  ## Richer transfer payment details

  Transfer responses now include IMAD and [payment details](/api-reference/brale/get-transfer#source-payment_details), making inbound ACH and wire reconciliation easier.

  ## Lighter-weight external bank payout setup

  External bank payout setup is now simpler for ACH credit, same-day ACH credit, and RTP. See [create an address](/api-reference/brale/create-address).

  ## Tempo and PulseChain support

  [Tempo](https://brale.xyz/blog/tempo-is-live) and PulseChain are now supported, expanding the set of networks available for Brale stablecoin workflows. See [transfer types](/coverage/transfer-types) for the full list.

  ## Brale MCP Server

  The [Brale MCP Server](https://brale.xyz/blog/brale-mcp-server) is now available, enabling developers to connect Brale workflows to AI-powered tools and agents.

  ## USDT on Tron

  Brale now supports [USDT on Tron](https://brale.xyz/blog/usdt-tron-support) for onramps and offramps.
</Update>

<Update label="2026-03-20" description="Week of March 17" tags={["New", "Update"]}>
  ## Tron support

  Brale now supports **Tron** as a transfer type. You can mint, burn, and transfer stablecoins on Tron mainnet and Tron testnet. Use `tron` and `tron_testnet` as `transfer_type` values in the API. See [transfer types](/coverage/transfer-types) for the full list of supported chains.

  ## USDT and RLUSD now available

  Two new third-party stablecoins are available as value types:

  - **USDT** (Tether USD) — issued by Tether
  - **RLUSD** (Ripple USD) — issued by Ripple

  You can now use these alongside Brale-issued stablecoins in transfers. See [value types](/coverage/value-types) for the complete registry.

  ## Transfer timing reference

  A new [transfer timing](/documentation/platform/transfer-timing) page documents cut-off times, settlement windows, and finality expectations for every supported transfer type — including fiat rails (wire, ACH, RTP) and onchain networks grouped by speed tier. Use it to set polling intervals and plan around settlement times.

  ## 20+ supported blockchains

  The platform now supports over 20 blockchain networks for stablecoin issuance and transfers, up from 14. See the full list in [transfer types](/coverage/transfer-types).
</Update>
